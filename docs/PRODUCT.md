## Идея

Пользователь в сообщениях VK описывает квартиру или дом (или загружает фото/чертёж),
задаёт параметры — бот возвращает:

1. **Планировку** (2D: схема комнат, размеры, зонирование).
2. **Обстановку по комнатам** (3D-визуализация или «фото интерьера» по стилю).
3. Для **дома** — этажность, комнаты на этаже, гараж, терраса и т.д.

> Юридически: это **визуальная подсказка / идея**, не проект для согласования в БТИ.
> В боте — явный дисклеймер.

## Рекомендуемые сценарии (MVP → v2)

### MVP (4–6 недель разработки)

| # | Сценарий | Ввод | Выход |
|---|----------|------|-------|
| A | **Квартира с нуля** | площадь, комнаты (список), стиль | 1 PNG план + 1–3 комнаты «меблировано» |
| B | **Одна комната** | фото пустой комнаты ИЛИ размеры + назначение | 1–2 варианта обстановки |
| C | **Дом 1 этаж** | площадь участка/дома, спальни, санузлы | схема этажа + фасад/гостиная (опционально) |

Пошаговый wizard в VK (кнопки + короткий текст), без mini-app на первом этапе.

### v2

- Несколько этажей дома, лестница, гараж.
- Редактирование: «убери диван», «стиль скandinavian».
- PDF «комплект» (план + лист по комнатам).
- Сохранение проектов «Моя квартира / Мой дом».

### v3 (если пойдёт трафик)

- VK Mini App или web-редактор плана.
- Импорт PDF/фото существующей планировки (OCR + AI).
- B2B: риелторы / застройщики (брендированные отчёты).

## Варианты реализации AI (на выбор)

### Вариант 1 — «Как Agrobotik» (рекомендую для старта)

- **Текст / параметры** → Grok (или другой LLM) формирует промпт и JSON-схему комнат.
- **Картинки** → API генерации изображений (Grok image, OpenAI, Stability).
- Плюсы: быстрый старт, один стек с Agrobotik.
- Минусы: планировки не всегда в масштабе; нужны шаблоны и постобработка.

### Вариант 2 — Гибрид «схема + красота»

- План: **программная отрисовка** (SVG/PNG из JSON: стены, двери, подписи).
- Интерьер: **AI только для рендера комнат** по согласованной схеме.
- Плюсы: читаемые планы, предсказуемые размеры.
- Минусы: больше кода (layout engine).

### Вариант 3 — Внешний SaaS

- Floorplanner / Planner5D API (если доступен) или аналог.
- Плюсы: качество планов.
- Минусы: лицензии, зависимость, дороже unit economics.

**Рекомендация:** MVP = **Вариант 2 lite** (JSON + простой SVG-план) + AI-рендер 1–3 комнат.

## Пользовательский поток (MVP)

```
Начать → Тип: Квартира | Дом | Одна комната
      → Площадь (м²) → Список комнат (кнопки + «другое»)
      → Стиль (сканди, лофт, классика, минимализм, …)
      → Бюджет (эконом / средний / премиум) — влияет на промпт
      → Подтверждение → генерация (лимит бесплатных)
      → Результат: план + превью комнат + «PRO / пакет»
```

### Объём MVP

4. Что **обязательно в первой версии**: только квартира, или сразу **дом**?
5. Нужен ли **ввод по фото** комнаты в MVP или только параметры текстом?

### Качество и формат

7. Достаточно **PNG/JPG** или нужны **PDF / SVG** для печати?
8. Нужны ли **размеры на плане** (3.2×4.1 м) или «условная схема»?
9. Стили интерьера — фиксированный список или свободный текст?

### VK и инфра

11. Хостинг: снова **PythonAnywhere** + Always-on?
12. БД: SQLite как у Agrobotik или сразу Postgres?

### Оплата (ЮMoney / ЮKassa)

13. **Отдельный магазин ЮKassa** или тот же shop_id, другие `metadata`?
14. Ориентиры по ценам: копировать Agrobotik (149/мес) или выше (дизайн дороже)?
15. Модель: **подписка**, **пакеты генераций**, **разовая «полная квартира»** — что предпочитаете?

### AI и лимиты

16. Какой **провайдер** уже есть ключи: Grok, OpenAI, другое?
17. Бюджет на **1 генерацию** (примерно): 5₽ / 15₽ / 50₽ — влияет на free tier.
18. Нужна ли **модерация** контента (NSFW, запрет лиц людей на фото)?

### Юридическое

19. Текст **дисклеймера** («не является проектом») — ваш юрист или шаблон?
20. Политика хранения фото пользователей (срок, удаление по запросу)?
